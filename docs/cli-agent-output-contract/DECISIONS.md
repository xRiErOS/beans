# Decisions — cli-agent-output-contract

Status icons: 🟣 open · 🔵 in progress · 🟢 decided · 🔴 rejected · 🟡 unclear

## Settled

| ID | Background | Decision | Rationale | Status |
|---|---|---|---|---|
| D01 | `beans-13ae` claims update gives back no state. M04–M06 show it gives back the full post-write bean. | Reframe 13ae: the defect is the **inconsistent JSON envelope across commands**, not a missing payload. | Left as written, an implementer would rebuild an existing function and ship an unnoticed contract break while doing it. | 🟢 |
| D02 | Both beans are the two halves of one question — what the CLI hands an agent on failure and on success. | One shared workspace: `docs/cli-agent-output-contract/`. | Deciding the error shape without the success shape produces two half-contracts. | 🟢 |
| D03 | The EARS-validator finding (prose "where" scored as a keyword, `~/.claude/skills/ce-beans-operationalize/scripts/ears-validator.js`) has no tracker of its own. | File it as a bean in this repo's `.beans/`. | PO call, pragmatism over repo purity: one tracker beats an unfiled defect. Noted as a foreign-repo defect in the bean body. | 🟢 |
| D04 | Collection language. | English, like the beans and commits. | `DESIGN.md` lifts into bean bodies verbatim; German prose around an English EARS block is exactly the seam the artifact-language rule exists to prevent. | 🟢 |
| D05 | Seven JSON shapes across ten commands (three bypassing `internal/output`). Consumer inventory (T01) found **zero** consumers that break on unifying. **And the shape has already caused damage:** in the okf-tools incident (Q07, cause 2) an agent read `beans create --json` through `.get('id','')`, got nothing because `id` sits under `bean`, concluded the creates had failed and duplicated three beans into orphans. `fixtures.ts:111`'s `(json.bean?.id ?? json.id)` is someone defending against the same trap locally instead of fixing it. | **Bare for single results, bare array for lists.** The envelope is reserved for genuinely multi-part payloads. `create`, `update`, `delete` change; `show`, `list` stay; `rename` collapses to one document. | The breaking-change objection that framed `beans-13ae` is unsupported by evidence, and a uniform shape is what makes `jq -r .parent` mean the same thing at every call site. | 🟢 |
| D07 | `beans-ra75` wants runtime errors to drop the usage block while invocation errors keep it. R16 shows the mechanism the bean prescribes cannot deliver that. R17 shows cobra already ships a better shape for unknown commands. | **Adopt cobra's own idiom for every error class:** one error line plus `Run '<command path> --help' for usage.` No usage block, no per-invocation flag mutation. | Copies an idiom already running inside the same binary instead of inventing a policy; 33 lines collapse to 2 for both error classes; nothing fragile to maintain. Supersedes ra75's AC-2, which must be rewritten. | 🟢 |
| D08 | `omitempty` drops empty `parent`/`tags`/`blocked_by`; the present/absent split is already arbitrary (`status` always, `type` not). One shared struct at `pkg/bean/bean.go:138-166`. | **Accept absence as the contract.** Correct 13ae's AC-1 wording instead of changing serialisation. | `Parent` is a `string` — dropping `omitempty` yields `"parent": ""`, not `null`. Real nullability needs `*string` and drags YAML frontmatter round-tripping with it. Disproportionate. Routine call, taken by the think session. | 🟢 |
| D09 | `beans-ra75` filed as `feature`; the PO called both "bugs". | `ra75` → **bug**. `13ae` stays `feature` after the D01 reframe. | The tool states at `root.go:22` that it is built for AI-first workflows; a 1:33 signal-to-manual ratio on the error path is that promise unmet, not a new capability. Steers `beans list -t bug` triage correctly. Routine call. | 🟢 |
| D11 | Q08: `rename --json` emits two top-level documents; `CLAUDE.md` documents it as an agent-facing caveat marked "not yet tracked as a bean". | **Fixed under D05** — one document per invocation. The CLAUDE.md caveat comes out as part of the change. | D05 is precisely the contract that makes this a defect rather than a quirk; leaving it would keep the instruction file teaching agents to work around our own inconsistency. Routine consequence of D05. | 🟢 |
| D12 | Q09: `rename`, `check` and `graphql` construct JSON without `internal/output`; `delete` hand-rolls an `output.Response{…}` literal. That absence of a single construction point is what let seven shapes drift apart. | **`internal/output` becomes the only place response shapes are constructed**, with a test asserting no command package encodes JSON directly. | Without an enforced seam the contract decays again the next time someone adds a command. The test is the contract; the decision is otherwise unenforceable. | 🟢 |
| D06 | Bundles Q04/Q10/Q11. With D05 making success bare and D07 shrinking stderr to two lines, the remaining question is what a *failure* looks like. Today an error is emitted twice: a JSON document on stdout and cobra's own print on stderr. | **Exactly one machine-readable artifact.** The error document keeps its own shape (`{success:false, error, code}`) on **stdout** — errors cannot be bare, so the envelope is the deliberate counterpart to a bare success. Cobra's stderr print is **silenced whenever `--json` is active** (`SilenceErrors`). Without `--json`, stderr keeps the D07 two-line form and stdout stays empty. | stdout is the protocol channel and already carries the error document; moving it to stderr would make `beans update --json \| jq` yield nothing on failure and break the pipe. Silencing the duplicate removes the redundancy without costing the human anything — the human is not passing `--json`. Resolves D06, Q04, Q10 and Q11 in one contract. | 🟢 |
| D13 | Q12: the hook-ergonomics defect that actually caused the incident — a `PreToolUse` deny discards the whole Bash call while its reason names one statement. | **Fixed immediately** in `~/.claude/hooks/git-enforce.py` (commit `fad35712`): `deny()` now enumerates every statement in the call and states that none of them ran. Verified against the original incident command; E1–E4 regressions and the single-statement path unchanged. | It cost four dropped mutations and two verification rounds, the fix is contained, and leaving it filed-but-unfixed would let the same misread recur in any repo. Out of this collection's scope but squarely in its causal chain. | 🟢 |
| D10 | `docs/` was excluded repo-locally via `.git/info/exclude:7` — a leftover from when the fork was still a PR candidate to hmans and its own docs would have polluted the diff. D14 (fork is the product) removed that reason. | Exclusion lifted; `docs/` is versioned. | An unversioned think collection cannot be handed to the next session or another machine — it would defeat the point of writing it. | 🟢 |
